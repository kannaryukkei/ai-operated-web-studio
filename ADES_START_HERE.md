# ADES START HERE

**One fresh ChatGPT conversation. Multiple specialist AIs. One final website.**

This is the standalone quick-start kit for ADES 2.0. Upload this one file to a completely new ChatGPT conversation and follow the first prompt below. You do not need to study the AWOS repository, copy several documents, install anything, create an API key, or complete a technical setup.

## 1. Start a fresh pilot

1. Open a **new ChatGPT conversation**. This new conversation becomes the only project gate.
2. Upload this `ADES_START_HERE.md` file.
3. Paste the **Lead kickoff prompt** below.
4. Give ChatGPT the business brief, interview notes, website links, photos and other materials you already have. Do not fill a long questionnaire.
5. ChatGPT will decide whether ADES exploration is worth using, identify the most valuable design questions, and prepare small assignments for any specialist models you choose to use.

## 4. How the lead keeps review lightweight

ChatGPT should not deeply inspect every generated file. The lead uses this sequence:

1. Read the small `ADES_CONCEPT` metadata.
2. Reject outputs that break the brief or repeat the same idea.
3. Visually inspect the genuinely different candidates at useful scale.
4. Keep, adapt or reject the ideas with short reasons.
5. Ask for another round only to investigate an important gap.
6. Stop when additional work is unlikely to add a new useful idea.
7. Synthesize one coherent direction, build one website and verify the final result.

There is no target count. Five or ten candidates are fine only when they add genuinely different value; one or two may be enough for a simpler brief. More output is not itself a quality metric.

## 5. Continuing after a model quota/session ends

Do not move the whole conversation to another model. Ask the lead ChatGPT conversation for a short **ADES resume packet** containing only:
- confirmed business facts and non-negotiable constraints;
- completed assignments and one-line concept hypotheses;
- KEEP / ADAPT / REJECT decisions;
- remaining design gaps;
- the next exact assignment.

Start a fresh temporary specialist chat, paste the universal specialist prompt and the new assignment, then return the resulting HTML to the same lead conversation. The original lead conversation remains the source of truth.

## 6. Operating mode and safeguards

At the start, the lead must declare one mode:

- **`client_service`** — real client work. Use only source-backed facts, authorised assets and approved claims. Do not fabricate business facts, testimonials, prices, ratings, credentials, results or contact details.
- **`studio_development`** — internal experiment. Synthetic facts/assets are allowed only when unmistakably fictional and demo-only. No public release, real outreach, production deployment, DNS change or spending is authorised.

In both modes, protect privacy, credentials, copyright, asset licensing and third-party rights. A specialist preview is never a client approval or a production release. Never include secrets, API keys or private customer records in an assignment.

## 7. Minimum expected result

ADES should deliver **one distinctive, useful, responsive, working website**, plus a concise report of what was actually built, tested and visually reviewed. The lead conversation is the project log. Temporary HTML previews are design inputs and may be discarded after useful lessons are captured.

No moodboard package, dashboard, workflow app, scoring database, permanent model leaderboard or API integration is required.
