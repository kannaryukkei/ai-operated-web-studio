## 3. Content and asset register

**Purpose:** Track each content item and its approval status. Missing photos are not a blocker; the register should identify a substitute.

| Content item | Required? | Source | Status | Approval / next action |
|---|---|---|---|---|
| Business name and description | Yes | Client | Pending / Approved | Confirm exact spelling |
| Logo / brand mark | Recommended | Client / create concept | Pending / Approved | Create typographic fallback if absent |
| Main offer / service list | Yes | Client | Pending / Approved | Confirm names and scope |
| Prices / packages | If displayed | Client | Pending / Approved | Confirm validity and conditions |
| Main CTA and contact | Yes | Client | Pending / Approved | Test destination |
| Hero visual | Yes | Client / AI / licensed stock / designed | Pending / Approved | Choose image to fit crop |
| Gallery / visual showcase | Yes | Client / AI / licensed stock / designed | Pending / Approved | Use concept visuals if no approved work |
| Differentiators | Yes | Client brief / draft | Draft / Approved | Avoid unsupported claims |
| Process steps | If useful | Client / draft | Draft / Approved | Verify real operating flow |
| Location / service area | If relevant | Client | Pending / Approved | Confirm exact coverage |
| Testimonials / reviews | Optional | Verified customer source | Pending / Approved / Omit | Never invent and present as genuine |
| Metrics / certifications | Optional | Verified source | Pending / Approved / Omit | Keep evidence or omit |
| FAQ | Recommended | Client questions / draft | Draft / Approved | Check policy accuracy |
| Legal / privacy copy | When applicable | Client / qualified adviser | Pending / Approved | Do not invent legal assurances |

Suggested asset statuses:
- `NOT STARTED`
- `REQUESTED`
- `RECEIVED`
- `GENERATING / SOURCING`
- `IN REVIEW`
- `APPROVED`
- `REPLACED`
- `NOT USED`

For portfolio demos, sample data and fictional scenarios may be created to demonstrate the website's capabilities. Mark them as sample/demo content. For a real client's public launch, the client must approve any business claims and factual content; simulated testimonials or metrics must not be represented as real.

## 6. Content / visual approval message

Use after presenting the information architecture or visual direction.

```text
PROJECT APPROVAL — [CONTENT / VISUAL DIRECTION]

Hi [Client],

This is the current [content structure / visual direction] for your Starter website.

Please review:
1. Whether the business information and main offer are accurate.
2. Whether the section order and key messages make sense for your customers.
3. Whether the primary call-to-action is correct.
4. Whether the visual direction feels appropriate for the brand.
5. Any item marked as sample, generated, or placeholder that needs replacement or explicit approval.

Please send one consolidated response by [date]:
- APPROVED, or
- APPROVED WITH THE FOLLOWING CHANGES: [list]

Work in the affected stage will continue after this approval. New sections, new integrations, or a complete change in direction may require a scope update.

Thank you.
```

## 9. Internal QA checklist

### Scope and content
- [ ] All agreed sections are present.
- [ ] Correct business name, logo, contacts, address, and service areas.
- [ ] All service/product descriptions and displayed prices are approved.

- [ ] Hero composition and image crop reviewed.
- [ ] Typography hierarchy is consistent.

## 13. AI task prompt — brief to website plan

Use the following prompt with the approved discovery brief attached:

```text
Act as a senior website strategist and conversion-focused UX planner.

Use only the attached discovery brief and approved client material as factual sources.
Do not invent factual business claims, prices, locations, policies, certifications,
reviews, statistics, or case results. Where content is missing, propose a clearly
labelled sample concept or ask for client confirmation.

Create:
1. A one-sentence website objective.
2. Primary audience and their main questions.
3. Recommended one-page section order.
4. Purpose of each section.
5. Draft headline and copy direction for each section.
6. Primary and secondary CTA recommendations.
7. Missing facts and client approval questions.
8. Visual opportunities and image-generation briefs.
9. Starter-scope risks that should be excluded or quoted separately.

Optimize for a useful, distinctive one-page site. Avoid generic filler.
Do not design or code yet.
```

## 14. AI task prompt — implementation and QA

```text
Act as a senior frontend engineer and web QA lead.

Use the approved scope, content map, design direction, and current project repository.
Do not change agreed scope without identifying the change and its impact.

Before editing:
1. Inspect the existing project structure and conventions.
2. Identify the exact files and components that need changes.
3. Preserve working behavior unless the task explicitly changes it.

Implement the task with responsive behavior, accessibility, performance, and
maintainability in mind. Do not add a backend, database, CMS, authentication,
payment, analytics, or new dependency unless explicitly in scope.

After editing:
1. Run install/build/test commands appropriate to the repository.
2. Test the target interaction and primary CTA.
3. Check mobile, tablet, and desktop layouts.
4. Check for horizontal overflow and broken assets.
5. Report changed files, tests run, failures, remaining risks, and any client
   decision needed.

Never claim a test passed unless it was actually run and the result was observed.
```
